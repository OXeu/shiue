## 保留与过滤规则

- 保留原始正文（包括换行和 `@昵称`）、公开昵称及提交时间；登录作者的昵称与旧站展示规则一致，优先使用 `user.username`。不依据文章发布日期改写评论时间。
- 去重限定在同一篇文章、同一作者内；正文只对换行、NFC 和首尾空白做比较用的规范化，保留的原文不改写。登录作者按旧账号编号区分，游客按昵称区分。相同内容保留最早时间，同时间保留最小旧编号。不同文章不相互合并。
- 人工逐条复核明确的测试、纯数字/乱码、无意义片段、纯问候/签到，以及与文章无关的纯引流推广。保留技术提问、部署问题、补充资料、感谢及实际批评，包括简短的“有点慢”等反馈；不以正文短、含“测试”或含链接为由一概过滤。
- 旧接口没有父评论或回复层级字段，因此按原站平铺形式恢复，正文里的 `@昵称` 保留为文本，不推测父子关系。
- 不导入 `guestEmail`、IP、游客网址、头像及账号资料，也不为历史评论启用邮件通知。源站内容未被修改或删除。

每个导入的评论文件带有 `legacy.source`、`legacy.feedId`、`legacy.commentId` 来源信息。完整计数、重复项对应的代表编号、过滤原因及原文 SHA-256 见 [迁移记录](../data/comment-migrations/legacy-xeu-life.json)。先去重再过滤，`duplicateOf` 指向去重阶段的代表编号，代表项也可能随后被过滤。被过滤正文不另存入仓库。

## 再次核对

```bash
node scripts/import-legacy-comments.mjs
node --test scripts/import-legacy-comments.test.mjs
```

导入工具默认只输出 JSON 计划，不直接修改文件。计划中的 `files` 是待新增的路径与内容；匹配后的现存评论会复用 UUID，重跑不重复导入；现存内容与源站不同、文章匹配不明确、出现新的回复层级时会报错，不能静默覆盖。

如果本地 DNS 将旧站解析至内网，可用 `--address` 指定经核实的该域名公网 IP；HTTPS 的主机名与证书校验仍保留。此次迁移核对了两家公共 DNS 后才使用公网地址访问，没有修改系统 DNS 或 hosts。

[人工过滤清单](../scripts/legacy-comment-exclusions.json) 绑定文章编号、评论编号与原文 SHA-256。源站同一条评论如果后来修改，需要重新复核过滤决定。以后再次迁移时，应先检查新计划中的评论；这次的人工过滤决定不自动用于新编号。

旧站公开文章列表之外的文章没有可恢复数据；本次不涉及更早的 Twikoo 数据库，也没有恢复本项目已删除的测试留言。
